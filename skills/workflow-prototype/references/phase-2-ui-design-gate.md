# Phase 2 — MANDATORY UI Design Gate (blocking)

**Skill used:** [dev-fe-developer](../../dev-fe-developer/SKILL.md)

Applies only if the prototype has a UI. **You MUST NOT write any prototype logic until the user has explicitly approved the visual design.**

## Steps
1. **Build a real, viewable UI mockup first.** Produce a static visual artifact the user can actually open — a standalone HTML/CSS file or an image — using [dev-fe-developer](../../dev-fe-developer/SKILL.md) guidance. Use realistic placeholder content; stub/hardcode all data and interactions. **Not** an ASCII sketch.
2. **Present it and ask for explicit confirmation.**
3. **Iterate fully on demand.** If the user requests any change (layout, copy, colors, components, flow), apply the edits and re-present the updated mockup. Repeat this edit-and-review loop as many times as needed.
4. **Do not proceed until the user explicitly says the design is approved.** Adjusting it later is fine, but this first approval is a hard gate.

→ Once approved, proceed to [Phase 3](phase-3-build-handoff.md).
